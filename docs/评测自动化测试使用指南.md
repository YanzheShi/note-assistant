# 评测自动化测试使用指南

> 本文档面向**使用者**：讲清楚怎么跑这套自动化评测、参数是什么、数据集怎么写、报告看哪些数。
> 设计背景与实现细节见 [`评测框架扩展方案-多轮+token+缓存命中.md`](./评测框架扩展方案-多轮+token+缓存命中.md)。

## 1. 它是什么

一套针对本 RAG 系统的**自动化评测脚本**，一条命令完成：

- **批量自动提问 / 回答**（支持多轮剧本）
- **检索质量指标**：MRR / nDCG@k / Precision@k / Recall@k
- **生成质量指标**：BLEU / ROUGE-L / 语义相似度（可选 RAGAS）
- **LLM Token 统计**：含**网关 token 缓存命中率**（prompt caching）
- **语义缓存命中率**（问答级，仅 agent 链路）

被测系统（检索 + LLM）全程**真实**，非 Mock。详见第 7 节。

## 2. 前提条件

跑之前三项必须就位：

| 前提 | 说明 | 不满足时的处理 |
|---|---|---|
| **Ollama 已启动** | 本地 embedding（bge-m3）走它，默认 `http://localhost:11434` | 检索/生成都跑不起来 |
| **ChromaDB 已索引** | vault 已切成向量存进 `data/chroma` | 没建过索引先跑下面命令 |
| **`.env` 配好 LLM 网关** | `AGENT_BASE_URL` / `AGENT_API_KEY` / `AGENT_MODEL`（agnes 那条） | 生成环节报错 |

若 ChromaDB 还没建索引，先全量建一次（需 Ollama）：

```bash
uv run python -m note_assistant.indexing.ingestor
```

## 3. 快速开始

```bash
# 默认：agent 链路 + 内置 10 题 + 全指标统计
uv run python scripts/run_eval.py
```

跑完会在终端打印四类指标（检索 / 生成 / Token / 语义缓存），并把完整报告落盘到
`./data/eval_report.json`。

## 4. 命令行参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--target` | `agent` | 评测链路：`naive`（RAGChain，history 串联多轮）/ `agent`（默认，含语义缓存 + session 串联） |
| `--dataset` / `-d` | `builtin` | 数据集：`builtin` 内置 10 题，或指向一个 JSON 文件路径 |
| `--output` / `-o` | `./data/eval_report.json` | 报告输出路径 |
| `--k` | `3 5 10` | 检索指标截断点，可传多个，如 `--k 3 5` |
| `--ragas` | 关 | 开启后用 RAGAS 框架算生成指标（默认用手写指标，更轻量） |
| `--verbose` / `-v` | 关 | 逐题打印明细，含每题 token 用量 |

示例：

```bash
# 用 naive 链路跑内置集
uv run python scripts/run_eval.py --target naive

# 跑自定义数据集，报告存到指定位置
uv run python scripts/run_eval.py --dataset data/my_eval.json --output ./data/my_report.json

# 逐题看明细
uv run python scripts/run_eval.py --verbose
```

## 5. 数据集格式

数据集是一个 JSON，结构如下：

```json
{
  "name": "我的评测集",
  "questions": [
    {
      "question": "什么是 RAG？",
      "golden_answer": "RAG 是检索增强生成……",
      "relevant_files": ["08-RAG基础概念.md"],
      "relevant_chunk_ids": [],
      "turns": null
    }
  ]
}
```

字段含义：

| 字段 | 必填 | 说明 |
|---|---|---|
| `question` | ✅ | 用户问题 |
| `golden_answer` | 否 | **人工参考答案**，仅用于算生成指标（BLEU/ROUGE/语义相似度），不是 Mock 输出 |
| `relevant_files` | 否 | 应该命中的文件列表，用于算检索指标（recall/precision） |
| `relevant_chunk_ids` | 否 | 细粒度命中（可选） |
| `turns` | 否 | 多轮剧本，见下 |

### 多轮剧本

把 `turns` 写成一轮一轮的列表，评测器会逐轮串联（naive 用 history、agent 用 session_id），
每轮独立算指标与 token：

```json
{
  "question": "什么是 RAG？",
  "turns": [
    {"question": "它和微调有什么区别？", "golden_answer": "..."},
    {"question": "那什么场景不适合用 RAG？", "golden_answer": "..."}
  ]
}
```

### 怎么演示「语义缓存命中」

数据集里把**同一个 `question` 出现 ≥2 次**，`run()` 开头只清一次缓存（`reset_cache()`），
同一 run 内后续重复问题会直接命中已缓存答案（跳过整条 graph，零 LLM 调用）。
示例见 `data/eval_cache_demo.json`（2 个唯一问题各重复一次）。

## 6. 报告解读

报告 JSON（`--output` 指定的文件）关键字段：

| 字段 | 含义 |
|---|---|
| `retrieval_metrics_avg` | 检索指标均值（MRR / nDCG / Precision / Recall） |
| `generation_metrics_avg` | 生成指标均值（BLEU / ROUGE-L / 语义相似度） |
| `token_usage_total` | **LLM Token 总量**：`prompt_tokens` / `completion_tokens` / `cache_creation_tokens` / `cache_read_tokens` / `total_tokens` / `llm_calls` |
| `llm_cache_hit_rate` | **LLM 网关 token 缓存命中率** = `cache_read_tokens / prompt_tokens`（token 级） |
| `semantic_cache_stats` | **语义缓存命中（问答级）**：`{enabled, hits, misses, hit_rate, size, semantic}` |
| `per_question[].token_usage` | 每题 token 差值；**缓存命中的题这里 `llm_calls=0`**，可直接看出省了多少调用 |

两种缓存命中率要分清：

- **LLM 网关 token 缓存**（prompt caching / KV cache）：网关返回 `cached_tokens`，命中率 = `cache_read / prompt`，写进 `llm_cache_hit_rate`。
- **语义缓存**（问答级）：相同问题跳过整条 graph，命中率 = `hits / (hits+misses)`，写进 `semantic_cache_stats`。

## 7. 真实 vs Mock 说明

- **实际跑 `run_eval.py` 全程真实**：agent 链路直接调 `runner.ainvoke`，真实 ChromaDB 检索 + 真实 Ollama 嵌入 + 真实 agnes 网关 LLM。日志里能看到真实 `HTTP 200` 打到网关与 Ollama，token 也是真实计数。
- **唯一会用到 Mock 的地方**：
  1. `--target naive` 时，若 `Generator` 初始化**失败**，脚本会 fallback 到 `MagicMock` 返回"演示答案（mock）"——正常情况不会触发；
  2. `tests/evaluation/` 下的**单元测试**为提速用 fake/MagicMock 替身，与真实评测无关。
- `golden_answer` 是人工参考，**不是**系统输出；系统被测答案始终是真实 LLM 生成的。

## 8. 常见问题

- **检索指标偏低 / recall=0**：检查 `relevant_files` 是否真在 vault 里（文件名要对得上），以及 ChromaDB 是否已索引最新 vault。
- **生成指标（BLEU/语义相似度）偏低**：开放问答 vs 教科书式 golden 字面重叠天然低，属预期，不代表管线故障；要看回答质量建议配合 `--verbose` 人工看逐题答案。
- **想省 credits**：复用问题触发语义缓存（见第 5 节），命中题不调 LLM。
- **`--target agent` 比 naive 慢**：agent 有多轮 reflect/rewrite 循环，每题多次 LLM 调用，属正常。
